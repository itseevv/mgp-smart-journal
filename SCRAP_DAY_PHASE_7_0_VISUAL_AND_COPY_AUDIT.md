Date: 2026-07-07

## Scope and Guardrails

This phase is audit-only. I inspected the current customer-facing Scrap the Day surfaces and did not redesign UI, change components, alter layout, migrate copy, or touch database/auth/local-date/texture-upload/export logic/migrations. The only intended filesystem change for this phase is this markdown report.

Primary surfaces audited:

1. Journal Home / Month Sheet
2. Daily Memory Stamp Detail
3. Create / Seal Today flow
4. Scrap Table / Finder Tool
5. Save / Share modal
6. Daily 9:16 export output
7. Customer mobile shell / journal background
8. Demo routes that render the same surfaces

Out of primary scope: PIN/recovery/auth surfaces. They are customer-facing, but the user explicitly excluded auth work and they are not one of the Phase 7 redesign surfaces.

## Part B - Visual Debt Against Product Principles

### Photo-first

- Daily detail photo area is inside a paper panel after date/title; the photo grid does not dominate the first visual read.
- Month Sheet renders only existing stamps, so empty sheet space is copy-led rather than a collectible visual object.
- Create flow starts with date/title fields before the photo commitment, even though the product concept centers the Cover Scrap.
- Save/share export reserves large vertical space for date/title and brand, and the stamp sheet can become smaller when title wraps.

### Premium editorial

- Typography has the right serif/sans direction, but sizes and tracking are component-local rather than a controlled editorial scale.
- Modal, create flow, photo viewer, and finder tool each have their own hierarchy rules.
- Export title/date fonts are hardcoded canvas strings, so the app/export type system can diverge.

### Tactile but not childish scrapbook

- `StampFrame` perforations are strong and repeated on tiny tiles, detail photos, crop aperture, and export output.
- Scrap Table hardware treatment is playful/chunky: plastic plate colors, handle tabs, punch animation, large radii.
- Empty/filler states use gradients and labels rather than quiet material surfaces.

### Leather / paper / photo material hierarchy

- Theme system separates leather and paper tokens, but many surfaces still use generic `.memory-entry` paper over the journal background.
- Paper texture is duplicated in `.paper-surface` and `.memory-entry`.
- App stamp edge CSS and export stamp edge canvas are separate implementations.
- Photo viewer drops into black full-screen media mode, outside leather/paper/photo hierarchy.

### Copy-light ritual flow

- Strong ritual phrases exist (`Seal Today`, `Cover Scrap`, `Find today's scrap`) but operational copy remains visible (`Uploading media`, `Private media cleanup`, `Retry cleanup`, MB prepared).
- Create flow has explanatory text on several surfaces: date helper, cover helper, additional moments helper, reorder helper, progress text.
- Duplicate/limit/error copy is helpful but verbose compared with the intended ritual tone.

### Consistent theme tokens

- Journal home/detail/month/export use `--journal-*` tokens.
- Create form, `memory-entry`, photo viewer, and Scrap Table mostly use base tokens or hardcoded colors.
- Export canvas has hardcoded rgba values for leather sheen, paper shadow, stamp rim, and perforation dots.
- Viewport theme color is fixed paper, not selected journal theme.

### Consistent image edge treatment

- Month tiles/detail/export use perforated stamp edges.
- Non-journal memory cards and photo collection use plain rounded rectangles.
- Photo viewer uses full-screen object-contain with no material edge.
- Cover picker empty state uses dashed border; cover preview uses stamp edge; sortable tiles optionally use stamp edge.

### Consistent buttons and links

- Primary actions vary: filled ink, filled journal-paper-text, filled journal-background, filled paper, bg-oxblood in legacy voice/admin contexts.
- Secondary links are mostly underlined but differ in color source and decoration.
- Navigation arrows are literal `<` and `>` text buttons instead of a shared icon button.
- Close buttons vary between pill text button, icon-only square, and circular full-screen controls.

## Part D - Component Refactor Candidates After Redesign

Recommended shared components:

- `JournalMobileShell`: keep, but make it own safe-area rhythm, theme background, viewport constraints, and optional shell density modes.
- `JournalIdentityHeader`: journal overline/title/rename lock area, reusable for home/demo and any future monthly export preview.
- `PaperPanel`: one paper material implementation replacing ad hoc `paper-surface`, `.memory-entry`, modal paper, and export paper assumptions.
- `MonthSheet`: orchestrates month title, navigation, empty state, CTA, and grid.
- `MonthTile`: single stamp tile with day marker, crop handling, empty/filler variant, and consistent edge.
- `PhotoGrid`: shared app/export grid model for Daily Memory Stamp, including cover crop rules and visible photo count.
- `MemoryStampCard`: app detail surface wrapper for title/date/grid/actions.
- `ScrapFinder`: extracted crop finder with theme/material tokens and less playful hardware styling.
- `RitualButton`: shared primary action for `Seal Today`, `Seal this day`, `Use this scrap`, `Save Image`.
- `TextLink`: shared underlined action/link styling for secondary actions.
- `IconButton`: shared close/nav/download/share controls, using existing icons or lucide if introduced later.
- `ExportPoster`: declarative model/component for the 9:16 output, so app preview and canvas rendering share composition decisions.
- `ExportActionSheet`: shared save/share modal shell.
- `PhotoFrame`: unified edge treatment for stamp/photo/paper variants, with CSS and canvas parity.
- `MaterialTokens`: formal token layer for leather, paper, ink, metal/accent, stamp edge, photo fill, shadow, and texture.

Priority order:

1. Tokens and material primitives first: `MaterialTokens`, `PaperPanel`, `PhotoFrame`, `RitualButton`, `TextLink`.
2. Product surfaces next: `JournalIdentityHeader`, `MonthSheet`, `MonthTile`, `PhotoGrid`, `MemoryStampCard`.
3. Export parity after app primitives: `ExportPoster`, canvas renderer sync.
4. Specialized tools last: `ScrapFinder`, `ExportActionSheet`.
