# Scrap Day Phase 7.2A.2 - Save/Share Modal Stability + Export Artifact Proportion Fix

## Scope

Focused production/playground parity fix for the Save/Share modal and Daily Export artifact proportions. Month Sheet, Create/Edit, Scrap Finder, database/auth/local-date logic, crop math, storage, migrations, and 9-image cap are out of scope.

## Pre-Edit Audit

### A1. Modal Positioning

- Save/Share modal is rendered by `components/export/daily-stamp-export-composer.tsx` as `DailyStampExportComposer`.
- The modal is mounted from `components/stamp/daily-memory-stamp.tsx` only when `exportOpen` is true.
- The overlay root already uses `position: fixed` via `fixed inset-0 z-50`, so it is not an in-flow child of the journal shell.
- The drift root cause is mobile alignment: the overlay uses `flex ... items-end ... sm:items-center`, so desktop is centered while mobile/tablet widths are bottom-aligned.
- The overlay currently uses `min-h-dvh`, but does not apply explicit safe-area padding rules beyond `px-3 py-3`.
- The overlay has no overscroll containment and does not lock background scroll while open.
- Modal content currently has `max-h-[84dvh] overflow-hidden`, so long content cannot scroll internally and max-height is not expressed as a safe viewport margin.

### A2. Mobile Shell Width

- `JournalMobileShell` is implemented in `components/journal/journal-mobile-shell.tsx`.
- Desktop CSS in `app/globals.css` sets `.journal-mobile-shell { width: min(100%, 30rem); }`.
- At `min-width: 640px`, shell uses `aspect-ratio: 9 / 16`, `height: min(calc(100dvh - 1.5rem), 53.333rem)`, and `max-height: calc(100dvh - 1.5rem)`.
- Pre-edit localhost desktop shell measured 480px wide by 853.31px high at 1280x900.
- iPhone 12 Pro and iPhone 14 measured 390px wide by 844px high.
- Samsung/Android measured 412px wide by 915px high.
- Demo route (`app/journal/demo/page.tsx`) and customer capsule route (`components/capsule/capsule-page.tsx`) both use the same `JournalMobileShell` component, so no separate shell-width implementation was found between demo/customer routes. Runtime customer-token measurement was not available from an arbitrary localhost token during the pre-edit audit.

### A3. Export Artifact Source

- The actual 9:16 export image is generated by `renderDailyMemoryStampExport` in `lib/export/daily-memory-stamp-export.ts`.
- The modal preview currently shows the generated blob URL through `<img src={composerState.previewUrl}>`, so production preview is already sourced from the actual downloadable artifact rather than a fake DOM recreation.
- The preview preserves `aspect-[9/16]` and uses `object-contain`.
- Current export canvas constants are `1080x1920`, PNG.
- Current pre-edit export tokens:
  - journal name: `61px` display font, centered in a 150px header band.
  - date: `35px` utility font.
  - title: `89px` display font, up to 2 lines, `86px` line height.
  - overlay: x/y derived from `shellPadding = 75`, `headerHeight = 150`, `overlayTop = 270`, `overlayPadding = 38`.
  - photo grid: `30px` gaps; 1 photo maxes at 900px; 2-4 photos use 2 columns; 5-9 use 3 columns.
  - logo: 291px square fitting box near bottom.
- These tokens are too close to direct app-scale visual proportions inflated into a 1080x1920 canvas. The title/date/journal name become visibly oversized in the downloaded PNG.
- Follow-up QA also found that unquoted canvas font-family strings caused the utility date font assignment to be ignored in some Chromium canvas renders. The date then inherited the previous large serif font, which made `AUGUST 31, 2026` visibly much larger than the Daily Memory Stamp app date.

### A4. Downloaded Artifact Dimensions

- Pre-edit Save Image download produced a valid PNG at `/private/tmp/phase-7-2a-2-pre-edit-download.png`.
- PNG dimensions: `1080x1920`.
- The modal preview and the downloaded image use the same generated artifact blob, so preview/download source parity is present before this fix.

## Root Causes

- Modal positioning drift: mobile overlay alignment is bottom-aligned (`items-end`) while desktop is centered (`sm:items-center`).
- Modal preview disproportionality: preview source parity is correct, but the underlying generated export artifact itself has oversized canvas tokens, so the miniature faithfully shows the wrong proportions.
- Exported PNG disproportionality: journal name/date/title/logo/grid gaps are scaled too large for a 1080x1920 artifact. The title also allows two lines, which crowds the overlay.
- Date font mismatch: canvas font strings did not quote font families with spaces, so the date did not reliably render with the intended utility font.

## Modal Positioning Fix

- Replaced mobile bottom alignment with a viewport-centered grid overlay in `DailyStampExportComposer`.
- Overlay now uses `fixed inset-0`, `display: grid`, `place-items: center`, `height: 100dvh`, `min-height: 100svh`, safe-area-aware top/bottom padding, and `overscroll-behavior: contain`.
- Modal surface now uses internal vertical overflow and `max-height: calc(100dvh - 1.5rem)`.
- Background scroll is locked while the modal is open by preserving/restoring `body` and `documentElement` overflow/overscroll styles.

## Preview Scaling Fix

- Production preview continues to render the actual generated export blob URL through a single `<img>` element.
- The preview image keeps `aspect-[9/16]`, `object-contain`, and `data-save-share-modal-preview-scale-source="full-artifact"`.
- Ready state no longer sets or renders `Image ready.`.
- Loading state remains one quiet line, `Creating image...`, on the leather/theme preview surface.

## Export Artifact Scale/Token Fix

- Added export-specific `dailyStampExportLayout` tokens derived from the accepted desktop 9:16 Daily Memory Stamp shell, whose 480px width maps to the 1080px export canvas at `2.25x`.
- Mapped the Daily Memory Stamp visual coordinates into the export artifact:
  - journal title center y: `77px`
  - overlay x/top/width: `27px / 153px / 1026px`
  - date font: `22px` utility font with tracked drawing
  - title font: `53px`
  - grid top/gap: `328px / 18px`
  - single-photo max width: `981px`
  - logo box: `220px`
- Title drawing is now single-line with ellipsis fallback through `drawSingleLineText`.
- Date drawing now uses quoted canvas font families and an Avenir/Helvetica utility stack to match the Daily Memory Stamp app date treatment.
- Photo grid rules remain unchanged: 1 photo uses one large square, 2-4 photos use 2 columns, 5-9 photos use 3 columns.

## Logo Handling

- Export continues to use `DAILY_STAMP_EXPORT_LOGO_SRC = "/brand/mgp-full-logo-transparent.png"`.
- This is the full transparent Modern Goddess Patina logo with text, not the icon-only mark and not the old opaque square logo.
- The full logo is recolored to deep burgundy on light/ivory themes and drawn from source on dark themes, matching the accepted playground handling.
